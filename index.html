01 — The map

How a piece of work moves

Here's the whole thing on one board. Work shows up as a GitHub issue. A timer on my Mac fires every 30 minutes, and each time it does, the factory does only what the dial allows — build, check, merge, deploy. Every step leaves a label on the issue, so I can read the whole story from my phone.

The dial

0 means everything runs by hand. At 1, it can open PRs. At 2, it can check them. At 3, it can merge green work and deploy. I turned it up one notch at a time, and before every notch the gate had to prove it could still fail. A gate that can't fail isn't a gate — same as a breaker you've never tripped.

The stop button

Two of them, on purpose. touch .factory/STOP works with the network down. Labeling any open issue factory:stop works from my phone in line at the store. And if the system can't read the stop state, nothing runs. Fail closed or don't bother.

The rules it can't touch

Three files govern everything: what the product is, how the factory has to behave, and how the code gets written. No agent can edit the rules it's judged by. Changing those files takes a human commit — and that's enforced in code, not on the honor system.

03 — When it broke

It broke once. Here's exactly how.

Anybody who tells you their autonomous system just works all the time is leaving something out. So here's my favorite failure.

Two PRs finished around the same time and both wanted the same migration number — like two subs claiming the same parking spot. I'd built a fix for that: on rebase, the factory renumbers the loser automatically. I tested it by hand. Worked great.

First time it ran under the scheduler, it fell over. The scheduler's environment didn't have node on its PATH, so the check couldn't run its own tooling — and it read its own failure as "duplicate migration found," then paged me with a story about a collision that never happened.

  • The fix wasn't clever. Resolve the tool with a full path, skip the check when a branch has no migrations at all, and — the real lesson — never let "my tooling broke" and "I found a problem" share an error code.
  • The regression test now pulls the live functions straight out of the running script, word for word, so the test can't drift away from the code it's testing.
  • The whole thing — bug, fix, and test — ships in the public repo below. I didn't sand any of it off.

What came out of it

A silent skip is a failure. Every check has to print a conclusion — ran and passed, ran and failed, or skipped and said why. An unattended system that skips quietly looks exactly like one that checked.

04 — The one tip

The system runs in parallel with my life

If I could hand you one thing from all this, it's not a prompt trick or a model setting. It's this: stop sitting there watching your agents. The time I save isn't minutes per task. It's that I'm never at the keyboard waiting on anything.

Three things make that real:

  • The only thing that reaches my phone is "needs a human." Everything else is the machine talking to itself. Notifications go local log first, then email, then Slack — and the notify script is written so the notification itself can never be the thing that fails. A dead webhook falls back to the log, not to an error.
  • The queue and the controls are all phone-shaped. Work goes in as a GitHub issue — I file them from the truck. The audit trail is labels. The stop button is a label. I can start, read, and stop the whole thing without opening a laptop.
  • When something really does need me, it's a 30-second check-in. I open a Claude Code remote session from my phone, look at what got parked, give it a nudge, and get back to whatever I was doing.

Here's the honest part of the tip, though. You can't walk away from agents you don't trust, and you shouldn't trust agents you haven't fenced in. The dial, the gates, the stop buttons — all that boring safety rail is exactly what buys the walking away. Same as a jobsite. Nobody supervises their way to safe. You build the system so the default is safe, and then you go live your life.

05 — The brain

My agents never relearn anything

The factory is half the story. The other half is that every session wakes up already knowing who it works for, what's been decided, and what's currently true — because the memory lives in a small git repo instead of somebody's chat history.

The loading trick is a ladder, and it's the only part that really matters:

  • Always: one small identity file — who I am, what I know cold, what's locked — and one global memory file with decisions and open questions.
  • Only when a project comes up: that project's state file. The active project gets depth; side projects get one page.
  • Only when named: the deep archive — decision records, prompt history, lessons. Never pre-loaded.

Decisions live in two sections — locked and open — and deciding something just means moving the line between them, with a date and a name on it. Every session ends with three lines in a daily log: worked on, decided, open. Thirty seconds of discipline, and the next session starts warm.

My real brain repo stays private — it's full of my business. But the pattern is public as a fill-in-the-blanks starter, loader skill included.

What to expect, honestly

  • It's not a framework. It's a working machine, and some parts are still shaped like the project it came from — ADAPTERS.md names every one.
  • It won't run unattended on day one, and it shouldn't. It starts at dial 0 with a human signing every piece of work. You earn each notch.
  • What you do get on day one: the gates, the judges, the protected-file guard, the stop buttons, and a binding procedure that refuses to finish until the gate proves it can fail.
